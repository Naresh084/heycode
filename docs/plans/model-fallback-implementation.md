# Explicit model fallback

`/fallback <provider> <model>` authorizes one session-local fallback route. `/fallback` reports its configuration and `/fallback off` disables it. The selected provider/model must be available and catalog-proven. Configuration is atomically stored beside the session with private file permissions.

The Agent attempts this route at most once per user turn, only after a definitive rate-limit, overloaded or server failure from an HTTP response or provider event. It refuses network/timeouts, authentication/protocol failures, explicit retry prohibition, any provider output, any current-turn client/server tool calls, audio routes and opaque-state transitions. Adapters must attest replay safety in their resolved call; legacy providers default to no fallback.

Routing persists and publishes the new selection through the settings owner before retrying the same user turn. Automatic writes compare the exact immutable settings snapshot, preserve command-line overrides and validate the fully resolved candidate before persistence. A settings reload, conflicting higher-priority field or failed write leaves routing unchanged.

Validation: seven composed production CLI tests cover normal continuation with one user event, durable routing, disabled/partial output refusal, one-attempt bound, invalid target rejection, forbidden replay, conflicting model pin and matching provider pin preservation. A settings regression proves project reload detection even with an unchanged user revision, override retention and no write on candidate rejection. Classifier unit coverage checks forbidden error classes and tool/output effects.

Cross-provider activation uses the production target factory during explicit configuration. Saved authorization is prepared in an effect-owned pre-step layer before the first request, without selecting the target. Failure is reported and leaves the primary usable. No provider construction occurs in the request-error fallback handler. Two composed real-adapter tests prove explicit and saved DeepSeek-to-Anthropic fallback with independent endpoint/key/options, one user turn, real read/result continuation, and no inference during preparation. A third path proves missing target credentials leave the primary usable. The complete fallback-filter run passes 12 tests, including three existing neighboring regressions.
