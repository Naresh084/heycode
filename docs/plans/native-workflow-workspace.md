# Native workflow workspace

A running workflow has one named rail below the composer. Its numerator counts successfully completed declared Agent nodes; its denominator includes queued Agent nodes and does not grow when a node retries. Down focuses the rail, Enter expands, and Alt+W or `/workflows` opens the same workspace. Escape backs out one view at a time and restores the parent's editor and cursor.

The expanded view uses the existing native theme: one quiet border, a phase column at approximately 29% width and an agent column at 71%. At 80 columns it stacks phase navigation above agent rows; at 40 columns it provides previous/next phase targets and scrollable agent selection. Every displayed phase and agent has a status word. Expanded views hide the duplicate workflow/task rails and composer. Active dictation retains its recording/transcription caption in both the workflow footer and screen-reader output. The native workflow layout was grounded in a [public Claude workflow reference](https://x.com/aehyok/status/2061013272577687581), with the [actual image](https://pbs.twimg.com/media/HJop7UDa0AETFZd.jpg) compared directly against rendered terminal captures.

Agent selection opens the exact resolved assignment and live/committed summary. C opens the existing child conversation by its recorded public task ID. Back retains phase, child selection and summary scroll. No label/time heuristic associates an agent or job. The service adapter uses the public owner-checked workflow projection and controls; closed handles alone are not successful steps, unreported usage is omitted, and failure never increments the successful-agent numerator. Native workflow jobs and children are excluded from duplicate generic footer counts while Ctrl+T retains their full task inventory.

P requests cooperative pause, R resumes committed progress, and X cancels through the existing WorkflowService. Requests do not optimistically declare success. The service acknowledgement and subsequent projection determine the displayed state. Approval, secret, plan-review and MCP questions retain priority. Keyboard controls work without mouse support, the workflow shortcut respects stored bindings, and the flat renderer exposes the same named phases, selected agent, assignment, result and actual controls.

Validation uses both reducer/renderer tests and `scripts/workflow_console_pty.py` (Python with pyte and Pillow). The native fixture starts the real CLI with a loopback HTTP model fixture, three independently gated child sessions, three declared phases and a real final report write. It captures actual PTY cells, ANSI output and screenshots at 120x38, 80x30 and 40x24; it does not synthesize the workspace from screenshots. The before baseline is 92ffd2a. The real three-agent journey passed: conversation round trips, mixed 1/3 and completed 3/3 agent states, cooperative pause, checkpoint resume, actual report write, draft/cursor return, queued 0/3 denominator, real Stop, multiple-workflow picker and restoration of the completed workflow. The final integrated journey result (local-only evidence: `docs/audits/assets/native-integration-2026-09-08/workflow-result.json`) records the tested revision, and its PNG/text captures are retained beside it. Reducer coverage includes 17 workflow interaction tests and two exact typed inbox-notice tests; strict TUI/UI clippy passed. Durable coordinator admissions supply every attempt job ID and its first committed End outcome, so fast resume and history replay do not depend on a live task-registry snapshot. Only known Completed, Paused or Cancelled attempts suppress their exact claimed routine Job inbox notice. Failed/unknown jobs and identical human text remain visible; inherited fork inbox events are outside the physical owner scope. Legacy logs without typed job admissions retain notices whose ownership cannot be proved.
