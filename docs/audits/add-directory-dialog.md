# Native session directory dialog

Bare `/add-dir` now opens a native path editor, then a separate **Grant for this session / Cancel** confirmation for the canonical directory. The explicit `/add-dir <path>` form retains its existing direct, human-command behavior. A headless caller receives a clear instruction to supply a path.

The confirmation uses the existing session workspace authority owner. Preview does not write the journal or grant file access. Confirmation rechecks the session revision, canonical path, directory identity, sandbox limits, and actual foreground/background/protocol admission. A successful grant changes the existing forwarding filesystem service without changing cwd or trusting the additional project's instructions. There is no global or persistent-all-sessions grant option.

The frontend bridge accepts only one attached terminal and one pending or active request. Closing the path/confirmation or detaching cancels it. A commit waiting for admission settles before the request lease is released. A commit that completed before a late Escape/detach reports success. The dialog consumes its own key/paste/mouse input; bracketed paste never submits and is bounded to one control-free path of at most 4096 bytes. Ctrl+U deletes the prefix before the cursor. Enter repeat events cannot confirm the grant immediately after path submission.

Higher-priority modals hide the dialog while retaining its request, and the terminal loop continues polling an in-flight commit. The coordinator owns the shared app, render, accessibility, and TUI-handle integration; the dedicated module owns path input, confirmation, rendering, and request lifetime.
