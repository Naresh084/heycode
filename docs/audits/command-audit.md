# Phase 2 slash-command completion audit

Date: 2026-09-11 (Australia/Melbourne)

This report closes the command-owned implementation pass for `P2-CM01` and every `P2-C-*` tracker row. It does **not** mark the mandatory Claude UI gate complete. The comparison source was the current official [Claude Code command reference](https://code.claude.com/docs/en/commands), read on 2026-09-11. The Phase 2 tracker and `docs/terminal-compatibility-requirements.md` remain the authoritative acceptance contract.

## Evidence boundary and dispositions

- **Implemented; UI open** means the dshx command has a real local handler and controlled evidence, but its applicable Claude interaction/presentation comparison is still required.
- **Partial; applicable follow-up** means a real adjacent dshx behavior exists, but the argument grammar, lifecycle, scope, or UI does not yet match the reference.
- **Applicable gap** means a useful local counterpart is still absent.
- **Deferred integration** means the reference command is tied to a hosted service, remote product, account/plan, or optional platform integration. Phase 2 must prove dshx does not falsely advertise it; it must not add a fake local command or require irrelevant Claude UI parity.
- **Not applicable** means promotional, billing, packaging, runtime-specific diagnostic, or otherwise non-core product behavior that dshx intentionally does not expose.

The dshx verification in this command-owned pass made no live production-provider call, external send, credential change, or hosted workflow. Controlled loopback/fake providers prove local dispatch only. Separately scoped current-Claude reference sessions were captured for `/focus`, `/color`, `/config`, and `/mcp`; they establish those reference interactions, not dshx provider behavior or blanket command parity.

## Implemented in the command-owned modules

### `P2-CM01` — central aliases and dynamic availability

The command descriptor now owns one central compatibility table. Registry lookup accepts aliases, canonical and alias collisions fail atomically for early and late registrations, and canonical inventory rows stay unique. `/help` renders accepted aliases and the current unavailable reason from the same dynamic availability snapshot used by the palette.

Accepted aliases are:

- `/new`: `/clear`, `/reset`
- `/quit`: `/exit`
- `/usage`: `/cost`, `/stats`
- `/keymap`: `/keybindings`
- `/list-agents`: `/peers`
- `/connect`: `/login`
- `/permissions`: `/allowed-tools`
- `/plugins`: `/plugin`
- `/resume`: `/continue`
- `/rewind`: `/checkpoint`, `/undo`
- `/schedule`: `/routines`
- `/background`: `/bg`
- `/tasks`: `/bashes`

Aliases resolve to the canonical handler and therefore inherit its `CommandTiming`; they are not separate handlers and cannot silently change a local command into a model turn. The coordinator-owned palette now scores canonical ids and aliases at the same priority and the TUI canonicalizes the resolved descriptor id before native/delegated special-case checks. This was required before enabling `/checkpoint` and `/undo` because a raw alias must not bypass the delegated-runtime guard around `/rewind`.

Remaining `P2-CM01` acceptance: run the live Claude/dshx command-menu comparison, retain keyboard and mouse evidence, and exercise available/unavailable/restored states. Controlled metadata tests do not close that UI gate.

### `P2-C-list-agents` — real current-session inventory

`/list-agents` is now distinct from `/agents`. It prints the current session identity and only the admitted child conversations owned by that session, including task id, label, lifecycle, provider, child session id, and background job id. `/peers` resolves to the same handler. It is discoverable but unavailable with a reason when the profile has no subagent registry. Team members and unrelated sessions are not invented; cross-session messaging remains a separate future integration.

### `P2-C-subtask` — real forked background child

`/subtask <task>` now validates a required bounded task, explicitly selects the native subagent provider, forks the parent context, admits a one-shot background job, returns stable task/job ids immediately, and delivers the settled result through the parent's durable follow-up inbox. It reports unavailable unless a fork-capable native provider and the background job host are both attached. Explicit native selection avoids an accidental precedence rule when direct and aggregate external subagent providers coexist.

This is intentionally `ModelScheduling`, so a mid-turn invocation queues at the existing safe command boundary. It is the only new command in this pass that starts inference, and it does so because that is the command's declared behavior.

### `P2-C-schedule` — explicit local durable schedules

`/schedule` and `/routines` now operate on the existing durable session schedule owner with an explicit non-conversational grammar: `list`, `after <seconds> <prompt>`, `at <unix-ms> <prompt>`, `every <seconds> <prompt>`, and `delete <schedule-id>`. The command is dynamically unavailable when that owner is not composed. It is `ModelScheduling` because creation can cause a later model turn; no argument is silently interpreted as a hosted or inferred routine.

This is a truthful local wrapper, not semantic parity with Claude's hosted conversational routine workflow. Update/run-now and hosted/account presentation remain outside the local command.

### `P2-C-autocompact` — live, bounded input-token threshold

`/autocompact` now reports the effective mode, accepts `auto` or a fixed threshold from 100,000 through 1,000,000 input tokens (`100`, `100k`, and `100000` are equivalent), persists the setting by exact revision, and applies it immediately to the running Agent. One shared controller adjusts both legacy-provider and strict-adapter budget paths while clamping the trigger to the model's usable input budget; it does not overwrite or inflate the model/context capacity. The command remains discoverable with a specific unavailable reason when automatic compaction is disabled by the active profile or Settings is read-only.

### `P2-C-scroll-speed` and `P2-C-statusline` — persistent live TUI controls

`/scroll-speed` opens a dedicated 0.25x–10x picker with arrow/tab adjustment, reset, a mouse-wheel ruler preview, exact-revision persistence, startup reload, and live signed fractional wheel movement. `/statusline` operates on dshx's existing built-in status and command-hint footer rows with explicit `on`, `off`, `hints on`, `hints off`, and `reset` actions; no arguments report the current state. It does not synthesize or execute a shell command and therefore remains a truthful local equivalent rather than a claim of Claude status-line semantic parity.

### `P2-C-add-dir` and `P2-C-cd` — real current-session workspace authority

`/add-dir <path>` adds one canonical filesystem root without silently loading that root's project instructions, skills, hooks, plugins, or profiles. `/cd <path>` moves the actual current-session cwd only within an authorized root. Both run through the workspace-transition owner, rebind production consumers, invalidate stale file observations, preserve durable scope identity, and refuse transitions that cannot safely recompose the active integrations. Paths containing spaces are accepted literally; shell expansion is not performed.

### `P2-C-focus` and `P2-C-color` — persistent focused transcript identity

`/focus` toggles a persisted compact transcript that retains the current user turn, condensed tool outcomes, the final answer, durable session title, and accessible equivalents while removing unrelated diagnostic history. `/color [color]` applies a current-session prompt/session identity color, including `default`, without changing the global theme. Both are TUI-only queued controls and create no model turn.

### `P2-C-insights` — bounded local structural report

`/insights` reads at most the newest 100 used active and archived sessions from the configured local store. It reports structural journal counts, token evidence quality, tool/route counts, creation cwd groupings, and mechanically observed friction. Forks count only their physical local suffix, so inherited parent events are not double-counted. The report emits no message text, runs no semantic inference, makes no network request, and explicitly labels unreadable sessions and unknown/partial usage.

### `P2-C-mcp` — direct stored-definition controls and bounded live reconnect

Argument-free `/mcp` still opens the real management panel. `/mcp enable <server>` and `/mcp disable <server>` dispatch through the exact `Arc<McpManagement>` attached to the running `AppState`, so there is no shadow store or second owner. Successful receipts explicitly say that the stored definition changed while current live connections remain unchanged until recomposition; configuration-declared, administrator-managed, unknown, and malformed targets retain the management layer's refusal semantics.

`/mcp reconnect <server>` now validates that exact managed name and dispatches to the product context's exact `Arc<McpRuntimeControl>`. The control retains only weak references to established stdio generations' existing `McpReconnectSupervisor`; it cannot extend a generation lifetime or create another retry owner. Admission is immediate and single-flight, while the existing bounded supervisor kills and replaces only the selected live child, refreshes the full tool generation atomically, and exposes readiness through `/mcp`. The command never infers or replays a model tool action. Disabled definitions, missing live generations, exhausted/shutting-down supervisors, absent runtime attachment, and Streamable HTTP transports retain explicit refusal states.

The MCP panel now owns its pointer and bracketed-paste input. Clicks select only visible servers, sections, actions, confirmation choices, and add/edit fields; they never run an action. Wheel input is accepted only inside the current panel body and moves only the focused server/action list. Paste is consumed outside forms and, inside a form, is control-stripped and bounded to the selected name or target field; it cannot activate, submit, or confirm. Height-aware line projection keeps the current server/action or form/confirmation, validation notice, paging state, and key hint reachable rather than silently clipping them. The complete unwindowed line projection remains the accessibility source.

### `P2-C-config` — one settings owner plus explicit provenance output

Bare `/config` now opens the same real schema-derived settings panel as `/settings` by emitting the existing `settings` capability-panel event; the status command retains its canonical id and the TUI command retains the separate settings owner, so no alias or registration collision is introduced. `/config show` preserves the complete read-only effective `ConfigReport`, including each value's file, command-line, or default provenance. Other arguments fail with `usage: /config [show]` rather than silently choosing a surface.

### `P2-C-reload-skills` and `P2-C-memory` — atomic trusted-source controls

`/reload-skills` rescans only the capability-bound skill roots and atomically publishes one complete generation shared by `/skills`, `/skill`, `load_skill`, and the next model-visible catalog. It reports exact added/removed/updated/skipped counts and only claims a prompt change when the model-visible projection changed. Root failures, contribution collisions, or workspace-authority drift retain the entire prior generation with source-scoped diagnostics.

`/memory` lists, shows, replaces, clears, and reloads fixed user/project instruction sources plus persistent per-preset auto-memory. It never accepts an ambient path. Writes require the exact revision returned by `show`; a workspace/trust change invalidates the edit. Symlinked, hard-linked, oversized, non-UTF-8, or unreadable sources are blocked or reported rather than silently trusted, and source labels do not expose absolute paths. This is a local trusted-instruction manager, not a claim of Claude's automatic-memory semantics.

### `P2-C-background`, `P2-C-fork`, and whole-session controls

On supported local Unix platforms, `/background` (`/bg`) and Ctrl+] detach the terminal while the same live session owner continues. Native `/fork` creates a durable conversation copy at a completed-turn boundary and starts an independent background owner while the parent remains active. `/branch [id]` retains the pre-existing create-and-switch conversation behavior. `/resume <id>`, `/tasks sessions`, and `/stop session <id>` explicitly attach, list, and gracefully stop whole-session owners without conflating them with jobs, terminals, agents, or structured work. Delegated-runtime forks and non-Unix hosting remain explicitly unavailable.
