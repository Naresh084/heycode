# Native direct-command turn boundary

A real CLI sequence of an ordinary prompt, `/skill alpha`, then another ordinary prompt could leave the TUI displaying Responding after the provider and Agent had completed. No skill preference mutation was required.

The retained failing fixture is `tmp/terminal-evidence/four-turn-finalization-interleave-20260911T192151Z-728ded/result.json`, using immutable v11. It records three requests, three flushed SSE terminal frames, three finished sockets, and three durable TurnEnd events, while the third visual turn stalls. The four-ordinary-turn control passes. The longer Skills sequence has the same boundary in `four-turn-finalization-skills-20260911T191914Z-83835c`.

The native runtime mirrors direct Agent commands into its shared event hub. AppServer retains a subscription between turns, but a direct model-scheduling command does not consume that subscription. The next AppServer turn could therefore consume the earlier command's TurnStarted and TurnFinished events as if they belonged to the new send.

The fix records existing native durable turn identities before starting the next AppServer pump and skips queued or replayed history until a new turn begins. It preserves the existing continuous subscription and its sequence normalization, and does not apply this native-journal rule to delegated runtimes. No timeout, synthetic completion, or provider retry was added.
